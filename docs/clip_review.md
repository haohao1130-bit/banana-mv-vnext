# 丹藥檢查：回爐、選丹、確認凝丹

## 三個獨立步驟

1. 勾選段落回爐：只生成候選毛片，保存 Seed、提示詞、workflow 及局部修改意見。不自動採用、不合成、不覆蓋目前完整 MV。
2. 逐顆預覽並按「選用此丹」：只保存待採用選擇。可以分多批回爐、重新開啟專案後再挑，原成片繼續可下載。選回目前成片版會取消此顆待採用選擇。下拉選單單純預覽，不等於選用。
3. 按「確認凝丹」：一次採用全部待選版本，其餘段落沿用目前版本，成功合成新的完整 MV。舊成片與所有候選均保留。沒有待選變更時不重複凝丹。

只有全部原段落完成後才能凝丹；不完整專案可先回爐保存候選、選丹，再續跑缺漏，最後確認。回爐或凝丹失敗保留原成片；成功候選可再挑。凝丹失敗保留待採用選擇，可修復問題後重試。執行階段中斷後開啟原專案，重新核對選擇再確認。

## 重拍基底與局部修改

每段修改建議最多 3000 字；留空只換 Seed。已有待採用選擇時，以該候選提示詞為重拍基底，否則以目前成片所用版為基底。單純預覽某版不改基底，需先按「選用此丹」。9B 只收當段原稿、意見、參考與局部時間，不重排全曲；修稿失敗不進入該段 H3 採樣。

連續勾選的末幀模式段落，後段使用本批前段新候選末幀；未同批生成的前段若已有待採用版，使用該版，否則使用目前成片版。候選記錄 previous_take。之後改選前段不會自動重拍後段，請看片核對接點。

## 儲存與版本

所有新版本直接存於同一工作資料夾：`00_raw_v1.mp4`、`00_part_v1.mp4`、`00_prompt_v1.txt`、`00_workflow_v1.json`；回爐依序新增 v2、v3，從不覆蓋舊版。目前成片用的版本為 selected_take，待採用選擇另外存於 status.json 的 pending_takes；選丹只記待採用版，不改目前成片或任何版本檔。確認凝丹直接合成選定的版本檔案，成功才更新採用紀錄，清空 pending_takes 並產生 final_vNNN.mp4；final.mp4 指向目前完整版本。

舊專案相容，不需重生故事或原片。新程式需重新載入；更新不會自動回復舊版已完成的自動採用操作。

## API

- GET /api/mv/status?id=...：列出各段 preview、takes、selected_take、pending_take，及專案 pending_takes。
- GET /api/mv/clip?id=...&index=0&take=original：無聲毛片，index 從 0 起算。
- POST /api/mv/retake：{id,indices,instructions?}，只生成候選。
- POST /api/mv/select-take：{id,index,take}，同步保存待採用選擇，不合成。
- POST /api/mv/condense：{id,revision?}，確認凝丹。前端傳 selection_revision，拒絕另一分頁更新選擇後的過期確認。

初次整首生成仍照原流程自動合成；此變更只拆開後續回爐與選版。離線測試不代表 GPU 品質已驗證。

舊專案的 takes 資料夾只作相容讀取；第一次回爐或凝丹時按既有版本紀錄複製到同目錄版本檔，舊檔保留。根目錄舊 RAW 只屬於初煉版，絕不配給回爐版。無法找到的版本不猜測替代。

例如選第1、3、5段 V2，其餘 V1，凝丹使用 00_part_v2 + 01_part_v1 + 02_part_v2 + 03_part_v1 + 04_part_v2。各段版號與完整成片 final_vNNN 分開累加。
